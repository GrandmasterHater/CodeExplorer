# Описание агента:


### Цель
Помощь в изучении кодовой базы группы проектов. Реализация RAG контура на основе кодовой базы для минимицзации галллюцинаций при ответах LLM и уменьшение затрат токенов на поиск информации в репозитории.  


### Ожидаемй результат
Агент способен отвечать на вопросы связанные с текущей информацией в кодовой базе. При поиске ответов агент самостоятельно выбирает инструмент поиска в зависимости от вопроса. Умеет состоявлять ответ на онове информации из нескольких источников(репозиториев). Умеет выполнять семантический поиск, полнотекстовый, объединять результаты и уточнять ответ анализом связей сущностей кодовой базы. 


### Состав проекта:

#### Агент

Представляет отдельный пакет. 

Отвечает за:
- Приём запросов от пользователя или другого агента и предоставляет сформулированный агентом ответ. Агент сопровождает выводы ссылками на источники, отделяет подтверждённые факты от предположений и явно сообщает о недостаточности, недоступности или противоречивости данных. 
- Выбор в каких репозиториях искать ответ. Выбор источников зависит от запроса и подключенных репозиториев.
- Подключается к нескольким MCP-серверам предоставляющим конкретные механизмы поиска.
- Выбирает источник поиска внутри самого репозитория (codegraph, codeexplorer или их комбинация).
- Предоставляет ACP протокол для подключения агента к IDE или агентской системе.
- Чтение исходных файлов для уточнение ответа.

Не знает про Qdrant, Tree-sitter и устройство индекса. Доступ к исходникам тоже получает через MCP, чтобы агент и сервер могли работать в разных окружениях.

Инструменты: Pydantic AI, Pydantic, LLM-провайдер, fastmcp.

Информация о рабочем пространстве хранится в json файле agent_workspase.json. Каждый отдельны репозиторий идентифицируется уникальным имененем, содержит краткое (не более 100 символов) описание репозитория, ссылку на root репозитория.

Агент НЕ отвечает за смысловую связь репозиториев. Предполагается что пользователь сам корректно задал агенту все необходимые источники. 

#### SemanticExplorer (Смысловая библиотека + поисковик)

Представляет отдельный пакет. 

Общий stateless-сервис для нескольких репозиториев. Каждый запрос явно определяет целевой репозиторий и параметры операции. Сервис не хранит контекст пользовательских сессий между запросами. Индексы, описания и метаданные актуальности сохраняются в постоянном хранилище. Параллельные запросы имеют изолированный контекст обработки.

Отвечает за:
- Инициализацию базы знаний: парсинг кодовой базы и индексация.
- Генерация описаний.
- Взаимодействие с семантической БД.
- Python API и MCP-интерфейс для поиска фрагментов кодовой базы и их описаний с указанием источников.
- Обнаружение изменений в репозитории (добавление, обнавлеие и удаление файлов).
- Обновление индекса при наличии изменений.
- Предоставляет структурированный результат поиска с указанием источников и актуальности информации.
- Гибридный поиск: семантический + полнотекстовый, объединение ранжированных результатов через RRF.

Во время переиндексации операции чтения затронутого индекса недоступны. Агент получает явное уведомление, сообщает пользователю об ограничении и при возможности продолжает работу с другими источниками. Агент не инициирует индексацию и не управляет её выполнением.

Инструменты: FastMCP, Qdrant, HTTPX, Pydantic, Tree-sitter и языковые грамматики (С#, Java, Python).

#### CodeGraphExplorer (Графовый поиск и анализ связей)

На данном этапе отдельнйы провайдер в составе агента. В будущем предполагается как отдельный пакет. 

Отвечает за:
- Чтение информации об узлах и их связях из направленного графа построенного по кодовой базе.
- Предоставляет структурированный ответ в зависимости от результата обработки запроса (сам ответ, актуальность информации).
- Предоставление исходного текста фрагментов кода.

Остальное на данном этапе остаётся за рамками пакета и реализовано выбранном инстурментом.

Инструменты: codegraph.

### Сценарии использования:

1. Инициализация проектов и конфигурация агента.
2. Запрос к кодовой базе для анализа связей.
3. Зарпос к кодовой базе по поиску смысла где требуется 1 репозиторий для получения ответа.
4. Запрос к кодовой базе по поиску смысла где требуется несколько репозиториев для получения ответа.
5. Запрос к кодовой базе когда обнаружена неконсистентность данных (устарели/обновились/отсутствуют).
6. Ответ агента когда не удалось найти ответа в базе знаний.
7. Ответ агента когда удалось не удалось найти смысловой ответ но можно сделать предположение по анализу узлов и связей.
